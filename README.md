# 毕设论文审核系统

面向学院毕业设计（论文）**全过程**的进度跟踪与审阅系统。当前版本先完成「账号与权限 → 学生与课题建档 → 材料提交 → 阶段审核 → 统计看板」这条主干，智能体审阅能力后续按节点逐个接入。

> 智能体不参与流程决策：它只产出建议（分数、意见、问题清单），**是否放行进入下一阶段由教师本人决定**。

## 版本线（两个分支）

| 分支 | 内容 | 用途 |
| --- | --- | --- |
| `main` | **无 AI 版**：全部常规功能（账号、建档、材料、审核、指导、统计、报表） | 交付 / 演示的稳定版本；不含任何 AI 代码 |
| `experiment/agent` | **AI 开发版**：在 `main` 之上叠加 AI 预审（LangChain / LangGraph 方向） | 只在实验线上开发 AI，验收通过后再合回 `main` |

约定：**与 AI 无关的改动先落 `main`，再合并进 AI 线**；AI 线新增的提交只应包含 AI 相关内容。这样任意时刻从 `main` 导出的版本都是一个功能完整、可独立运行的系统。


## 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 后端 | Python 3.12 · FastAPI · SQLAlchemy 2.0（async）· Alembic · Pydantic v2 | 全 Python 栈，后续 LangChain / LangGraph 可直接同进程调用 |
| 数据库 | PostgreSQL 16 | 本机原生安装，开发期 `127.0.0.1:5432` |
| 认证 | JWT（python-jose）+ bcrypt（passlib） | 三角色：ADMIN / TEACHER / STUDENT |
| 前端 | Vue 3 · Vite · TypeScript · Element Plus · Pinia · Vue Router · Axios | 学术风视觉：深墨蓝 + 暖纸色 + 衬线标题 |

## 快速开始

```bash
# 1. 数据库：确认本机 PostgreSQL 16 服务已启动（服务名 postgresql-x64-16）
#    首次需建业务账号与库：
#    CREATE ROLE thesis LOGIN PASSWORD 'thesis_dev_pwd';
#    CREATE DATABASE thesis OWNER thesis ENCODING 'UTF8';

# 2. 后端
cd backend
cp ../.env.example .env          # 填 JWT_SECRET
python -m venv .venv && .venv/Scripts/activate
pip install -r requirements.txt
alembic upgrade head
python -m app.db.seed            # 内置账号
python -m app.db.seed_demo       # 可选：24 名演示学生，仅供看板预览
uvicorn app.main:app --port 8000 --reload

# 3. 前端
cd frontend
npm install
npm run dev                      # http://localhost:5173
```

Windows 上也可以直接双击 `start-dev.bat`：脚本会检查数据库服务与端口占用，分别起前后端窗口，8 秒后打开浏览器。

- API 文档：<http://127.0.0.1:8000/docs>
- 健康检查：`GET /api/health`

## 业务流程（九节点）

```
选题/双向选择 → 任务书下达 → 开题报告/开题答辩 → 中期检查 → 查重检测
→ 论文定稿 → 评阅 → 答辩 → 归档/评优
```

其中 **选题 / 开题 / 中期 / 查重 / 定稿** 五个节点后期可能接入智能体审阅，界面上用金色圆点标注（`AI_STAGES`）；其余节点始终人工流转。

## 接口约定

- 统一响应体：`{ "code": 0, "message": "ok", "data": ... }`
- HTTP 状态码如实返回（401 未登录、403 越权、422 参数错误），前端据此分支
- 业务异常 / 参数校验异常 / 文件异常由全局处理器转成友好文案

- [x] **概览看板**：管理员后台框架（侧栏 + 顶栏）、九节点流程分布、指标卡、最近登录
- [x] **P2 学生与课题建档**：学生档案 CRUD、学生账号开通、课题录入、教师「我的学生」、学生「我的档案」
- [x] **P3 材料中心**：学生按环节上传（自动版本号）、教师/管理员查看下载、九环节覆盖情况
- [x] **P4 阶段审核**：教师按学生当前环节「通过 / 退回」，通过推进到下一环节（末环自动归档），退回必须写原因并留在原环节；`stage_reviews` 留痕（含材料版本），学生「我的档案」看到退回提示与最近记录，管理员「阶段流转」只读查看全校进度
- [x] **P5 统计报表**：管理员「统计报表」——五项指标、九环节明细、指导教师工作量（通过率 / 最近审核）、近 14 天提交与审核动态、一键导出 CSV
- [x] **P6 系统完善**：账号管理（教师 / 管理员账号创建、启停、重置密码，含自我保护规则）、操作日志查询（业务动作全量留痕）、批量导入学生（逐行校验 + 错误行定位）、列表空状态统一

- [x] **P6.7 阶段流转合并**：去掉「待处理 / 流转记录」两个 Tab，合成一张在途学生表——顶部按姓名学号、环节、指导教师筛选，行内直接看九环节进度条、材料、指导次数与上次流转；管理员点姓名或「详情」进学生详情页追溯完整审核历史与逐次沟通明细（时间、方式、内容、证据）

- [x] **P6.11 教师详情页可读性**：还没进入中期检查的学生只显示「中期检查：未开始」，不再提前报「还差 10 次」；阶段材料表把本环节置顶并标「本环节」，学生在该环节最近一次审核之后新交的材料标「新提交」并整行淡金底，本环节审核区同步提示新提交时间与材料名，老师不必逐条比对时间

## 说明

- 阶段审核只能由**该学生的指导教师本人**执行：智能体只出建议，放行权在人；管理员只读，便于监督与统计。
- 「待审核」的判定是**材料时间晚于最近审核时间**（`ReviewsView.vue` 的 `isNewSubmission`）：学生重交后又会重新变成待审核，退回后未补交则不再标红，避免列表永远挂着一堆待办。
- 催交的口径和「待审核」互补：本环节没交，或退回后没有重交，才算「该催」；已经交了等审核的不催。提醒只落在系统内（没有短信 / 微信通道），学生下次登录在工作台或材料页就能看到，教师在列表里能看到每条催交的时间。批量催交按**当前筛选结果**执行，先筛环节再点更精准。
- 学生详情页的「待核对材料」用的是同一口径（`StudentDetailView.vue` 的 `currentStageReviewAt` / `isNewMaterial`），按材料名只认最新版本；中期进度条按学生所处环节分「未开始 / 统计中 / 已通过」三种形态，只有到达中期检查才参与通过校验。
- 中期检查是**唯一有硬门槛**的环节：通过前该生必须有 ≥「参数配置」里设定的 `MIDTERM` 指导记录（默认 10 次，`config_service.get_midterm_min`），不足时返回 422 并提示还差几次；证据截图非必填，但建议留痕。
- 教师档案四项在 `account_service._ensure_teacher_profile` 里统一校验，手机 `1[3-9]\d{9}`、邮箱做基本形状校验（`x@y.zz`，不引入额外依赖）；历史教师由迁移按「计算机学院 / 软件工程」回填，邮箱按账号生成占位，首次编辑时需按实际补全。
- 教师分两类已由老师确认：`SUPERVISOR`（**指导老师**）带学生、做全部阶段审核；`REVIEWER`（**就业老师**）目前在本系统不承担任何审核任务，只保留账号身份与工作台说明，管理员可在「账号管理」创建、筛选、切换身份。中文文案只有 `backend/app/models/enums.py` 的 `TEACHER_TYPE_LABELS` 和 `frontend/src/constants/teachers.ts` 两处，学校再改叫法时改文案即可，代码值和数据不用动。
- 系统参数存在 `system_settings`（key-value + JSON），默认值写在 `backend/app/services/config_service.py`：库里没有记录就按默认值走，所以新环境不用预置数据。读取统一走 `config_service`（按列查询，避免刚 commit 的实体属性过期触发同步加载），业务代码不直接查表。
- 环节截止日期只做**提醒与统计**，不改变流程：学生逾期仍可提交，教师仍可审核；中期检查的最少沟通次数是唯一真正拦人的参数，改小后只对之后的审核生效。
- 账号停用只禁止登录，不删除：历史材料、审核记录、日志都要能追溯到人；管理员账号不能停用自己，也不能停到只剩零个启用管理员。
- 审计日志的动作名存英文常量（`LOGIN` / `STAGE_APPROVE`…），中文文案在前端 `constants/actions.ts` 翻译，改文案不影响历史记录。
- 批量导入每行固定 6 列：`学号,姓名,专业,班级,年级,指导教师账号`，**指导教师必填**（教师账号不存在或已停用会整行跳过），表头可留可删；一个学号填错不会拖垮整张名单，错误行会带行号和原因返回。
- 改密后已签发的 JWT 仍然有效（无状态令牌不查库），改密只影响下次登录；如需立即踢下线，后续可加 `token_version` 字段在依赖里比对。
- 统计报表的口径写在 `backend/app/services/report_service.py` 顶部：材料数含历次版本、通过率 = 通过 / 审核总数（无记录显示 —）、平均审核时长按“该环节最新材料提交 → 教师处理”计算，没交材料直接放行的不计入。
- 「数据概览」和「统计报表」的分工：概览是**实时看板**（此刻在途、今日动态、最近登录），报表是**历史分析与导出**（分布、趋势、工作量、逾期）。报表数据一次全量返回，图表用 `components/EChart.vue` 按需注册 ECharts 模块；Excel 由后端 `export_service.build_workbook` 生成（多 Sheet、冻结首行），PDF 由前端截屏分页（`html2canvas` + `jspdf`，避免服务端处理中文字体），分页时优先在面板边界断开，不会把一张图切成两页。
- 审核记录只增不改，`material_version` 记录审核当时该环节的版本号，材料后续替换也能回溯“当时看的是哪一版”。
- 教师详情页复用管理员的学生详情组件（`views/admin/StudentDetailView.vue`），靠 `isTeacher` 与路由 `?from=reviews` 切换返回文案、侧栏高亮与操作面板；后端仍按导师身份二次校验，前端显隐只是一层体验。

- 智能体只出建议、放行权在人：`ai_runs` 是**独立于审核记录**的旁路数据，AI 结果不参与任何状态流转判定，教师通过 / 退回仍走 `reviews` 接口。
- 模型调用会自动重试（`AI_RETRY_TIMES`，默认 1 次），只针对"再试一次可能就好"的错误：超时、429 限流、5xx、输出被截断、连不上接口。重试成功时 `attempts=2` 且错误清空（界面显示"第 2 次尝试"）；仍失败则保留最后一次原因并注明"共尝试 N 次"。key 无效（401）、余额不足（402）不重试，直接告诉老师怎么处理。
- 单次输出上限 `AI_MAX_TOKENS`（默认 4000）。一份开题报告正常输出 2500-3600 tokens，接近上限；接口返回 `finish_reason=length` 时说明 JSON 已经是半截的，这里主动判失败并重试，不会把它解析成"0 分"存进库。
- 演示或断网环境把 `AI_PROVIDER` 改回 `mock` 就能离线跑；真实模式下每份报告约 1800 输入 + 3600 输出 tokens（一次几分钱），`AI_DAILY_LIMIT` 兜底，`AI_ENABLED=false` 直接关掉整块。
- 预审只接**开题报告**（`ai_service.SUPPORTED_STAGES`），其余环节上传不解发预审；PDF / DOCX 可直接抽文本（DOCX 用标准库 zipfile + ElementTree 解析，不引新依赖），`.doc`、图片、压缩包和扫描件（可读字数 < 80）会落 `SKIPPED` 并给出人话原因，不占用额度。
- 每条预审都落 `provider` / `model` / `prompt_version` / `raw_response`，改 prompt 后旧记录仍可解释；prompt 放在 `backend/app/agents/prompts/proposal_v1.md`，改版就新增 `proposal_v2.md` 并升 `PROMPT_VERSION`，不覆盖历史。
- 额度与开关：`AI_ENABLED=false` 整块关闭（接口返回 enabled=false，前端不渲染 AI 卡片）；`AI_DAILY_LIMIT` 只统计今天成功入队的次数，学生上传触发的与教师重跑的都算。
- API Key 只放 `.env`（已被 git 忽略），`/api/ai/status` 只回 `has_key` 布尔值，日志里打印掩码；交付 / 部署时用环境变量注入，打包用 `git archive`，不要把 `.env` 打进压缩包。
- 数据库变更一律走 Alembic，不用 ORM 自动建表。
- 主题色与字体集中在 `frontend/src/styles/theme.css`，组件内只引用变量。
- 上传文件默认落在 `backend/data/uploads/<学生ID>/<环节>/`，目录名用随机 UUID，原始文件名只存数据库；`data/` 已被 git 忽略。
- `seed_demo` 生成的 24 名学生是**虚构演示数据**，用于看板预览，P2 之后应以管理员录入的真实名单为准。
